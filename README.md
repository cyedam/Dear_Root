# Dear Root

> 잎이 보내는 신호를 읽고 뿌리부터 다시 돌보는 맞춤 케어 쇼핑몰
> 식물이 시드는 이유를 몰라 헤매는 초보 식집사가 7문항 '맞춤 케어 체험'으로 원인을 찾고, 식물의 종류와 증상에 맞는 흙·영양제와 돌보는 방법까지 한 번에 알 수 있게 만든 반응형 웹

- **담당 범위**: 홈페이지 기획 → Figma 와이어프레임 작성 → 바이브코딩 구현 → GitHub Pages 배포

## 3. 사용 기술

- **React, Vite**: 페이지·섹션을 컴포넌트로 나눠 관리하고, 빠른 개발 서버로 수정 결과를 바로 확인하며, 4개 페이지(메인 · 맞춤 케어 체험 · 케어 제품 · 케어 가이드)를 주소로 이동하기 위해
- **GitHub Pages**: 무료 배포, main에 push하면 자동 빌드·배포
- **Figma**: 와이어프레임 작성 · 디자인 시안
- **Claude**: 바이브코딩 (화면 구현), 이미지 생성 프롬프트 작성
- **GPT Image**: 히어로 실사 식물 이미지 제작
- **Google Flow**: 흙 장면, 상품 사진, 질문 카드 · 가이드 일러스트 등 사이트 이미지 제작

## 4. 주요 기능

- **인터랙티브 히어로**: 실사 식물 잎을 앞·중간·뒤 겹으로 쌓아, 마우스를 따라 바람에 흔들리고 스크롤하면 흙 → 햇빛 장면으로 끊김 없이 이어짐. 글씨를 숨기고 배경만 보는 월페이퍼 모드 제공
- **맞춤 케어 체험**: 3단계 7문항(식물 종류 · 증상·벌레 · 환경) 카드 선택 → 주원인 · 가장 먼저 할 일 · 벌레 대처법 · 추천 흙·영양제까지 결과로 안내. 추천 카드를 누르면 케어 제품의 해당 탭으로 바로 이동
- **나만의 흙 만들기 (DIY)**: 재료 8종을 스쿱 단위로 담으면 흙 봉투에 재료 층이 쌓이고 배수 · 보습 · 영양 막대와 결과 문구가 실시간으로 바뀜. 모바일에서는 재료 목록이 바텀시트로 전환
- **케어 가이드**: 물 주기 · 햇빛 · 분갈이 요령을 식물 종류 6가지별로 펼쳐 보기, 벌레 7종 대처법, Q&A 질문 남기기 · 내 질문내역 확인 가능
- **반응형 · 터치 대응**: 1440 / 1280 / 1024 / 768 / 480px 단계별 레이아웃, 터치 기기에서는 hover · 흔들림 효과를 줄이고 '동작 줄이기' 설정 존중
- **몬스테라 잎 커서**: PC에서 마우스를 따라오는 잎 커서, 켜기 · 끄기 가능

## 5. 트러블슈팅

### 이슈 1: DIY 섹션, 모바일에서 재료를 담으면 결과가 보이지 않음

- **문제**: 작은 화면에서는 재료 목록이 길어, 재료를 담는 동안 흙 봉투와 결과가 화면 밖으로 밀려남
- **원인**: 데스크탑 배치를 그대로 세로로 쌓아 재료 목록과 결과가 멀리 떨어져 있었음
- **해결**: 재료 목록을 화면 아래 바텀시트로 옮기고, 처음 재료를 담을 때 제목과 흙 봉투가 시트 위에 보이도록 한 번만 자동으로 맞춤. 담으면서 결과를 바로 확인할 수 있게 함

### 이슈 2: 맞춤 케어 체험에서 카드를 잘못 누르면 바로 다음 질문으로 넘어감

- **문제**: 단일 선택 카드를 누르자마자 넘어가 실수로 고른 답을 되돌리기 번거로웠고, 다중 선택 질문과 조작 방식도 달랐음
- **원인**: 선택과 이동이 한 동작으로 묶여 있었음
- **해결**: 카드는 선택만 되고 '다음'을 눌러야 넘어가도록 단일 · 다중 선택 방식을 통일. 이전 · 다음 버튼을 화면 아래에 고정하고 질문 카드도 한 화면에 들어오게 해, 버튼을 찾아 스크롤하지 않아도 되게 함

### 이슈 3: 히어로 위에서 상단 메뉴 글자가 배경과 겹쳐 보임

- **문제**: 메뉴를 화면 위에 고정하자, 히어로 장면이 밀려 올라가는 동안 메뉴 글자가 식물 사진과 겹쳐 읽기 어려웠음
- **원인**: 메인에서는 메뉴 배경이 투명이었음
- **해결**: 히어로가 지나가는 동안에는 반투명 흰 바탕 + 뒤 흐림(blur) 효과를 넣고, 다 지나가면 흰 바탕으로 바꿈

## 6. AI 활용 방식

- **맡긴 일**: 기획 문서(목적 · 구조 · 와이어프레임 · 디자인 · 퀴즈 로직)를 `PROJECT_CONTEXT.md` 한 파일로 정리하고, 이를 바탕으로 React 컴포넌트 구현 · 인터랙션 · 반응형 처리 · 배포 설정까지 진행. 히어로 실사 이미지와 일러스트 생성 프롬프트 작성
- **진행 방식**: 목적·범위 확인 → 페이지 설계 → 디자인 → 에셋 → 인터랙션 → 반응형 → 배포 7단계를 한 단계씩 진행하고, 단계마다 결과를 확인·승인한 뒤 다음으로 넘어가도록 규칙을 정함. 없는 내용은 지어내지 않고 질문하게 함
- **핵심 프롬프트**: "PROJECT_CONTEXT.md를 먼저 읽고, 제작 진행 규칙대로 한 단계씩만 진행해 줘. 비어 있는 항목은 선택지와 추천안을 함께 보여 주고 물어봐 줘."

## 7. 회고

- **배운 점**
  - 기획 내용을 md 파일로 정리해 두니 AI가 정해진 규칙에서 벗어나지 않았고, 불필요한 수정을 최소화한 결과물을 만들어 냈다. 수정할 때마다 문서도 함께 고쳐 화면과 문서의 괴리를 줄일 수 있었다.
  - Figma로 구조와 디자인을 잡고, Claude로 구현하고, GPT Image와 Google Flow로 각 스타일에 맞는 이미지를 만드는 식으로 도구마다 맡을 일을 나눠 적재적소에 활용하는 능력을 쌓았다.
- **아쉬운 점**
  - 히어로 인터랙션을 더 자연스럽게 다듬고 싶었지만 원하는 만큼 완성하지 못해 아쉽다. 다양한 인터랙션을 다루는 방법을 확인 후 적용해야 한다.
  - 장바구니와 결제 기능도 계획했지만, 이번 사이트의 핵심 기능이 아니라고 판단해 뺐다. 다음 홈페이지를 만들 때는 일반 쇼핑몰처럼 기본 기능을 모두 넣어보겠다.
