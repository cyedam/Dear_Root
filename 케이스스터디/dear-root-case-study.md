## 2. 기획 의도

- **배경**
  - 초보 식집사는 다양한 흙과 영양제, 넘쳐나는 식물 관리법 사이에서 어떤 것이 본인의 식물에게 맞는지 정확하게 파악하기 어려워하고 고민만 쌓이게 됩니다. 식물을 건강하게 기르고 싶은 식집사를 위해 상품 판매보다는 정보 제공을 주로 제공하고 싶었습니다.
- **목표**: 방문자가 "몰라도 괜찮다, 같이 봐줄게요"라는 다정하고 편안한 느낌을 받는 것.
  - 가장 중요한 행동: 맞춤 케어 체험을 끝까지 해서 내 식물의 케어 결과 받기
  - 보조 행동: 체험 결과로 나온 흙 · 영양제 구매 (이번 범위는 구매 버튼까지만)
- **타깃 페르소나** (가상 페르소나)
  - 기본 정보: 김하은 (가명), 20대 후반, 회사원, 식물을 키운 지 3개월
  - 상황
    - 이사 선물로 친구에게 몬스테라 화분을 받으며 처음 식물을 키우게 됐습니다.
    - "물만 잘 주면 된다"는 말을 듣고 흙 상태와 상관없이 자주 물을 줬습니다.
    - 요즘 잎이 노랗게 변했는데, 무엇을 잘못했는지 모르겠습니다.
    - 식물을 잘 모르지만, 하나씩 배워 가며 오래 키우고 싶습니다.
  - 이 사이트를 사용하는 상황
    - 퇴근 후 집에서 노래진 잎을 보고, 노트북으로 원인을 찾다가 들어옵니다.
    - 전문 용어를 몰라도 그림 카드로 지금 식물 상태를 고르고, 원인과 가장 먼저 할 일을 확인합니다.
    - 결과를 보고 물 주는 법과 분갈이 시기를 케어 가이드에서 더 찾아봅니다.
  - 원하는 것
    - 가능한 한 돈을 들이지 않고 관리할 수 있는 방법을 쉽게 알고 싶습니다.
    - 꼭 필요할 때만, 내 식물에 맞는 흙이나 영양제를 사고 싶습니다.
  - 불편함 (페인포인트)
    - 식물이 시들어도 이유를 몰라, 지금 무엇부터 해야 할지 알 수 없습니다.
    - 흙과 영양제 중 무엇이 내 식물에 맞는지 몰라, 고르지 못하고 망설입니다.
    - 물 주기 · 햇빛 · 분갈이 요령이 식물 종류마다 달라서, 내 식물 기준의 방법을 찾기 어렵습니다.
    - 경고성 문구를 보면 선물받은 식물을 죽일까 봐 불안해집니다.
    - 원인을 알기도 전에 구매 버튼과 할인 문구가 먼저 보이면, 사야만 해결되는 것 같아 부담스럽습니다.
- **배경과 목표의 연결**: 겁주거나 먼저 팔려는 정보 대신, 질문 몇 개로 원인을 같이 찾아 주는 경험을 사이트의 중심에 두었습니다. 그래서 체험은 앞에, 구매 버튼은 결과 내용 뒤에 둡니다.

## 3. 핵심 가설

- **가설 설정 배경**: 체험 질문을 카드형으로 정한 이유는 "초보자가 글보다 그림으로 쉽게 고를 수 있게" 하기 위해서였습니다(99). 일러스트로 정한 이유는 실사 벌레 사진은 징그러울 수 있고, 아이콘은 뜻을 전하기 어려워서입니다.
- **IF**: 맞춤 케어 체험의 질문을 일러스트 카드로 보여 주고, 카드를 누르면 선택만 되고 화면 아래 고정된 "다음"으로 넘어가며, 위쪽 진행 표시("n / 7")가 매번 바뀌면
- **THEN**: 초보 식집사는 7개 질문에 끝까지 답하고 결과 화면("진단 결과")까지 이동할 것이다.
- **검증 방향**: 메인의 "맞춤 케어 체험 시작"부터 결과 화면까지 막힘 없이 가는지 사용 흐름 테스트(TC-20)와 질문 이동 테스트(TC-08 · TC-09)로 확인합니다.

### 인터랙션 1. 맞춤 케어 체험 질문 카드 (03 가설의 IF)

- **무엇을**: 3단계(식물 종류 · 증상·벌레 · 환경) 7문항을 일러스트 카드로 고릅니다. 카드를 누르면 초록 2px 테두리 + 그림자로 선택 상태가 되고, 화면 아래 고정된 "다음"을 눌러야 넘어갑니다. 답을 고르기 전에는 "다음"이 비활성입니다. 위쪽 진행 표시("n / 7")와 막대가 질문마다 바뀝니다. Q2 · Q3은 여러 장을 고를 수 있습니다.
- **왜**: 초보자가 글보다 그림으로 쉽게 고르게 하고, 지금 몇 번째인지 보여 주어 끝까지 가게 하기 위해서입니다. 처음에는 단일 선택 카드를 누르면 바로 다음으로 넘어갔지만, 실수로 고른 답을 되돌리기 번거롭고 질문마다 조작이 달라 헷갈려서 "다음" 버튼 방식으로 통일했습니다.
- **어떻게**: React 컴포넌트로 질문 · 답 상태를 관리합니다. 데스크탑에서는 남은 화면 높이를 카드 줄이 나눠 가져 스크롤 없이 한 화면에 들어오게 했고, 이전 · 다음 버튼은 모든 화면에서 아래 고정 막대로 두었습니다. 결과 내용은 `99-care-quiz.md`의 원인 판단표(우선순위: 벌레 · 밑동 무름 → 물 → 온도 → 빛 → 영양)를 따릅니다.

### 인터랙션 2. 메인 히어로 바람 · 스크롤 장면

- **무엇을**: 실사 식물을 앞 · 중간 · 뒤 겹으로 쌓아, 마우스가 지나가면 그 자리에 바람이 일어 잎이 휘었다가 천천히 돌아옵니다. 마우스가 없어도 잎이 살랑입니다. 스크롤하면 배경이 아주 조금 아래로 움직이며 흙이 드러나고 "케어 제품 바로가기"가, 더 내리면 조금 위로 움직이며 햇빛이 들고 "케어 가이드 보기"가 나타납니다.
- **왜**: 목적 문장의 "잎이 보내는 신호"를 첫 화면에서 눈으로 보여 주고, 흙(뿌리) → 햇빛(잎) 흐름으로 브랜드 이름(Dear **Root**)과 "뿌리부터 다시 돌본다"는 이야기를 스크롤로 전합니다. 장면과 이동할 곳이 짝지어져(흙 → 케어 제품, 햇빛 → 케어 가이드) 버튼을 읽기 전에도 어디로 가는 길인지 알 수 있습니다. 히어로 앞에는 로딩 화면을 두지 않아 체험 시작 버튼이 늦게 보이지 않게 했습니다.
- **어떻게**: three.js 같은 라이브러리 없이 `<canvas>` 한 장에 **WebGL2**로 직접 그립니다. WebGL2가 안 되는 브라우저에서는 일반 2D 캔버스로 그립니다.
  - **식물 배치**: 실사 식물 사진 22장을 미리 줄여 한 장의 텍스처로 모으고, 5겹(맨 뒤 키 큰 식물 · 가운데 큰 잎 · 뒤 · 중간 · 앞)으로 세웁니다. 겹마다 배경색 섞기 · 채도 · 밝기 · 흐림 · 그림자를 셰이더에서 다르게 처리해 깊이감을 냅니다. 맨 뒤의 흐릿한 숲은 움직이지 않는 그림으로 한 번만 그립니다.
  - **바람**: 마우스를 늦게 따라오는 두 점(Codrops 방식)을 잇는 선을 64 × 40칸 '바람 지도'에 찍고, 그 자국은 1초 안팎으로 옅어집니다. 식물은 잎 끝 자리의 바람만큼 밑동을 축으로 휘었다가 용수철처럼 살짝 출렁이며 돌아옵니다. 앞 겹일수록 세고 빠르게 움직입니다.
  - **잔잔한 흔들림**: 마우스가 없어도 화면을 가로질러 지나가는 바람결과 그루마다 빠르기가 다른 하늘거림을 섞어 계속 살랑입니다.
  - **스크롤 장면**: 300vh(터치 기기 200vh) 구간에 화면을 고정해 두고 스크롤 양을 0~2 진행도로 바꿉니다. ① 흙에서는 흙 단면 사진이 아래에서 올라오고, ② 햇빛에서는 배경이 밝아지며 오른쪽 위에서 금빛 빛줄기(React Bits의 SideRays, WebGL)가 퍼집니다. 배경 이동은 26px입니다.
  - **기기별 처리**: 터치 기기에서는 마우스 바람을 끄고, 잔잔한 흔들림 폭을 40%로 줄이고, 멈춰 있을 때는 초당 20번만 그립니다. '동작 줄이기' 설정에서는 바람과 흔들림을 모두 끕니다.
  - 계산 방식은 문서(08 · 09)로 먼저 설계한 뒤 구현했습니다. 문서는 three.js를 제안했지만, 실제로는 라이브러리를 쓰지 않고 WebGL2로 직접 구현했습니다.

### 인터랙션 3. 나만의 흙 만들기 (DIY)

- **무엇을**: 재료 8종(상토 · 부엽토 · 코코피트 · 질석 · 펄라이트 · 마사토 · 바크 · 훈탄)을 + / − 버튼으로 1스쿱(0.6L)씩 담습니다(한 봉 6L = 10스쿱). 담을 때마다 흙 봉투에 재료 층이 쌓이고, "n / 10 스쿱", 배수 · 보습 · 영양 막대, 결과 문구("물이 잘 빠져요. 배수용 흙에 적합해요" 등)가 바로 바뀝니다.
- **왜**: 맞춤 케어 다음가는 두 번째 아이덴티티라 케어 제품 페이지 맨 위에 두었습니다. 배합이 어떤 식물에 맞는지 담는 순간 보여 주어, 흙을 잘 몰라도 직접 섞어 볼 수 있게 했습니다. 결과 말투는 틀린 배합이라고 하지 않고 더 좋아지는 방법을 제안합니다.
- **어떻게**: 결과는 부피 비율 기준 판단표(바크 60% 이상 → 난초용, 배수 재료 60% 이상 → 배수용 …)로 정합니다. 1100px 이하에서는 재료 목록을 화면 아래 바텀시트로 바꾸고, 처음 재료를 담을 때 한 번만 제목 위치로 맞춰 흙 봉투와 결과가 시트 위에 보이게 했습니다.

## 8. 바이브코딩 구현

- **협업 방식**: 기획을 `PROJECT_CONTEXT.md` 한 파일로 정리해 AI에게 넘기고, 7단계로 나눠 단계마다 결과를 확인 · 승인한 뒤 다음으로 넘어갔습니다. 한 번에 맡기고 끝내지 않고, 묻고 답하고 고치는 대화를 여러 번 주고받았습니다.
  - **AI가 묻고, 내가 정하기**: 문서에 비어 있는 항목은 AI가 선택지와 추천안을 함께 보여 주며 물었고, 제가 골랐습니다. 바로 정하기 어려운 것은 '미정'으로 두었다가 그 항목이 필요한 단계에서 다시 정했습니다. 이렇게 정한 답은 날짜와 함께 문서에 남겼습니다(2026-11-13 · 11-16 · 11-17 답변).
  - **화면을 보고 다시 요청하기**: 단계마다 결과 화면을 직접 보고 "승인 / 수정 요청 / 다시 하기"로 답했습니다. 질문 카드를 누르면 바로 넘어가던 동작, 히어로 글자 색, 제목 글꼴, 햇빛 장면의 빛 색과 세기처럼 실제로 써 보고 어색한 부분을 하나씩 다시 요청했습니다.
  - **AI의 제안을 걸러 받기**: 모바일 처리처럼 AI가 인터랙션마다 '유지 · 축소 · 제거'를 제안하면, 그대로 받지 않고 항목마다 제가 골랐습니다. 예를 들어 잔잔한 흔들림은 끄지 않고 줄여서 남겼습니다.
  - **문서도 같이 고치기**: 화면이 바뀔 때마다 `PROJECT_CONTEXT.md`도 함께 고쳐, 다음 작업에서 AI가 바뀐 내용을 기준으로 이어 가게 했습니다. 요구사항 정의서와 테스트 케이스도 같은 방식으로 만들었습니다. 테스트 문서가 개발자용으로 어렵다는 점, 다른 문서를 열어 봐야 하는 단계가 있다는 점을 짚어 처음 보는 사람도 따라 할 수 있게 다시 고쳤습니다.
- **구현 환경**: JavaScript, React 19 + Vite 8, react-router-dom 7, 기본 CSS, GitHub Pages(GitHub Actions) / Claude, GPT Image, Google Flow
- **내가 설계한 것**
  - 기획 문서 체계: 목적(01) → 구조(02) → 사이트맵(03) → 와이어프레임(04) → 레퍼런스(05) → 디자인(06 · 07 · 98) → 체험 질문(99)을 먼저 쓰고, 구현에 필요한 것만 `PROJECT_CONTEXT.md`로 모음
  - AI 작성 규칙: 문서와 답변에 있는 내용만 쓰고 지어내지 않기, 빈 항목은 선택지와 추천안을 함께 보여 주며 묻기, 내용마다 출처 적기, 화면이 바뀌면 문서도 바로 고치기
  - 제작 진행 규칙: 목적 · 범위 → 페이지 설계 → 디자인 → 에셋 → 인터랙션 → 반응형 → 배포, 한 단계씩 승인 후 진행
  - 화면 구조와 이동: 페이지 · 섹션 · 버튼 ID(P1-B1 등)와 목적지 연결표, 핵심 행동 동선
  - 체험 로직: 7문항 구성, 답 조합 → 원인 판단표와 우선순위, DIY 배합 결과 판단표
  - 핵심 프롬프트: "PROJECT_CONTEXT.md를 먼저 읽고, 제작 진행 규칙대로 한 단계씩만 진행해 줘. 비어 있는 항목은 선택지와 추천안을 함께 보여 주고 물어봐 줘."
- **AI에게 맡긴 것**
  - 기획 문서를 `PROJECT_CONTEXT.md`로 정리
  - React 컴포넌트 구현, 인터랙션 코드, 반응형 처리, 배포 설정(`vite.config.js`의 기본 경로, 배포 워크플로)
  - 레퍼런스 사이트 분석(05), 히어로 인터랙션 계산 방식 정리(08), 작업 지시서(09)
  - 현재 코드 기준 인터랙션 32개 목록과 모바일 처리 제안(유지 · 축소 · 제거, `docs/interaction.md`)
  - 히어로 실사 이미지 · 일러스트 생성 프롬프트(10 · 98)
- **내가 직접 판단하고 수정한 것**
  - 단일 선택 카드 자동 넘김 → "다음" 버튼으로 통일
  - AI의 모바일 제안 중 결정: 잔잔한 흔들림은 끄지 않고 줄여서 유지, 마우스 · 트랙패드가 연결된 태블릿은 마우스 효과를 켬, 터치 기기 메인 스크롤 구간을 300vh → 200vh로 줄임
  - 히어로 앞 로딩 화면: 시안을 만들어 적용했다가 버벅임 때문에 뺌
  - 레퍼런스에서 가져오지 않을 것(어두운 배경, 로딩 화면, 강한 움직임 등)과 움직임 세기('가까이' 따라오기, '최소한으로' 움직이기)
  - 표현: '처방' 대신 '맞춤 케어', 메뉴 이름 '케어 세트' 대신 '케어 제품'
  - 제목 글꼴 교체(학교안심 뜀틀 → 태나다체), 히어로 글자 색(제목 #234D35 · 설명 #4A5D23)
  - 히어로 식물 배치: 화면을 칸으로 나눠 칸마다 한 그루씩 두되 칸 안에서 위치를 조금씩 흔들어(칸 폭 ±40%) 줄 맞춘 느낌을 없앴습니다. 같은 종류는 화면 폭의 4.5%(최소 40px) 안에 붙지 않게 했습니다. 가운데는 키 작은 식물, 가장자리는 키 큰 식물이 더 자주 나오게 해 문구 자리를 비웠습니다. 비어 보이는 자리(오른쪽 위 · 왼쪽 끝 · 양쪽 가운데)는 몬스테라 알보로 채우고, 가운데 둘은 옅게 두어 글자를 가리지 않게 했습니다.
  - 햇빛 장면의 빛: 빛줄기 효과는 React Bits의 SideRays를 직접 찾아 골랐습니다. 처음 빛은 사이트 색과 어울리지 않는 푸른빛이었고, 너무 강렬했습니다. 그래서 따뜻한 금빛으로 바꾸고 세기를 낮췄습니다. 빛은 오른쪽 위에서 퍼지고, 빛줄기는 마우스 방향을 따라 흔들립니다. 터치 기기에서는 처음 퍼지는 연출 뒤 멈춘 그림으로 둡니다.

## 10. 가설 검증

- **처음과 끝을 연결하는 서사**: 시드는 이유를 몰라 겁부터 나는 초보 식집사가 그림 카드로 지금 자기 식물의 상황을 고르고, 원인과 가장 먼저 할 일을 직접 찾아가게 했습니다. 스스로 답을 찾는 과정이 "나도 돌볼 수 있겠다"는 동기가 되고, 겁주는 경고 대신 "몰라도 괜찮다"는 안심을 주는 경험을 만들고 싶었습니다. 결과를 본 뒤에는 케어 가이드에서 돌보는 법을 더 알아보고, 꼭 필요할 때만 맞는 흙 · 영양제를 고를 수 있습니다. 사야 해결되는 사이트가 아니라, 배우며 오래 키우게 돕는 사이트가 되는 것이 목표였습니다.
- **검증 근거**: 메인의 체험 시작 버튼부터 7문항을 거쳐 결과 화면까지 가는 사용 흐름 테스트(TC-20)와 질문 이동 테스트(TC-08 · TC-09)가 모두 통과했습니다. 사용자 테스트 21개 중 실패는 없었습니다.
- **확인한 범위와 한계**: 핵심 흐름(우선순위 상 · 중)은 동료 1명이 데스크탑에서 안내 없이 테스트했고, 우선순위 하는 직접 확인했습니다. 모바일 화면은 실제 휴대폰이 아니라 개발자 도구의 반응형 모드로만 확인해서, 실제 터치 조작감이나 기기 성능은 확인하지 못했습니다. 이번 테스트는 정해진 절차대로 했을 때 기능이 의도대로 동작하는지를 본 것입니다. 실제 초보 식집사가 스스로 끝까지 가는지는 관찰하지 않았고, 체험 완료율 같은 수치 지표는 범위에서 뺐습니다(`prd.md`). 그래서 THEN은 "끝까지 갈 수 있는 길이 막히지 않았다"까지 확인한 것입니다.
- **마무리 한 문장**: "식물 관리를 잘 몰라도 누구나 끝까지 할 수 있는 쉬운 체험으로 전하고 싶었습니다."
